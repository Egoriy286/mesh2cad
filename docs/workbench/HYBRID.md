# Гибридный ввод геометрии

Ветка `hybrid` продолжает рабочую версию, слитую из `egoriy` в локальную `main`.
Она реализует гибридный ввод для существующего GPT-backend. Нативный 3D-проектор
CAD-Recode и POD–QDEIM здесь не реализованы и не выдаются за работающие режимы.

## Что получает модель

- `images`: существующие виды исходника, габариты и запрос. Для правки — код
  выбранного родителя, метрики и при необходимости ошибка исполнения.
- `hybrid`: тот же контекст плюс детерминированный JSON `hybrid-v1`, измеренный
  на оригинальном нормализованном `target.stl`, а не на упрощённом превью.

Измерения включают bounds/extents, сечения X/Y/Z на 25/50/75% соответствующего
габарита, полилинии с признаками замкнутости и усечения, копланарные группы
треугольников, гипотезы цилиндров и 64 равномерно выбранные по площади точки с
нормалями. Плоскости не утверждают связность. Цилиндры — ограниченная эвристика
для осей X/Y/Z, а не распознанные CAD-операции. Нормали следуют ориентации
треугольников; winding не исправляется. Вложенные замкнутые контуры могут
представлять отверстия, но их роли не классифицируются автоматически.

Все координаты остаются в системе исходника: центр bounding box в нуле,
наибольшая сторона равна единице. Предсказание независимо не выравнивается.
Единицы исходного STL неизвестны. Оценка CAD использует полный оригинальный mesh.

## Подготовка и происхождение

`POST /api/jobs` с `kind=prepare_input` запускает только локальную подготовку,
без ключа, сетевого обращения, резерва расходов и создания CAD-версии. Этот путь
доступен из диалога «Ввод модели». Подготовка также автоматически предшествует
платному гибридному запросу. При ошибке или превышении лимита платный вызов не
запускается; скрытого перехода на изображения нет.

Работа выполняется в отдельном процессе с ограничениями времени и ресурсов,
с возможностью отмены. Кэш `assets/<id>/hybrid-v1.json` привязан к SHA256 точных
байтов `target.stl` и версии схемы, записывается атомарно. Частичный результат
не принимается за готовый. Размер канонического JSON для модели ограничен
32 KiB; потеря деталей отмечается признаками усечения и предупреждениями.

`GET /api/assets/{id}/evidence` читает только проверенный кэш и возвращает
`{status: ready|preparing|unavailable, evidence, summary?}`. Чтение не запускает
вычисления. Состояние приложения содержит только краткую сводку; полный JSON
не пересылается в интерфейс при каждом опросе.

Настройка `input_mode=images|hybrid` копируется в задачу при отправке. Старые
задачи без поля сохраняют режим `images`; старым версиям без записанного
происхождения оно не приписывается задним числом. Новые версии и JSON/CSV-отчёты
содержат фактически использованный режим, provider/model/reasoning, признак
вызова модели и хеш измерений. Demo, ручное исполнение и переоценка отмечаются
как действия без ввода LLM. Изменение настройки не меняет старую версию.

## Протокол сравнения

1. Выбрать один и тот же импортированный mesh. Зафиксировать модель, усилие
   рассуждения, запрос и число попыток (сначала одну).
2. Выбрать `Изображения` и выполнить «Построить CAD». Экспортировать отчёт.
3. Выбрать `Гибрид`, проверить подготовленный JSON и выполнить «Построить CAD».
   Эта кнопка начинает с нуля без кода предыдущей версии. Не использовать
   чат-правку для независимого сравнения вводов.
4. Сравнить IoU, Chamfer, H95/F-score с одинаковыми параметрами оценки,
   долю исполняемых CAD-программ, сохранение отверстий, время и измеренную
   стоимость. `null`/недоступная метрика не считается нулём.
5. Повторить на нескольких деталях и нескольких генерациях: один случай
   не доказывает превосходство метода. Не смешивать Demo/ручные/переоценённые
   версии с независимыми генерациями и не менять число попыток между методами.

Платный A/B-эксперимент не запускается автоматически при установке, подготовке
или просмотре данных. Транспортные тесты используют подставной backend.

## Проверка реализации

Полный регрессионный набор: 134 теста. В нём проверяются реальные локальные
сечения блока, цилиндра, сферы и кольца с отверстием; ограничение 32 KiB;
детерминизм и происхождение кэша; отмена и тайм-аут; состав подставного запроса
к модели; отсутствие платного вызова при ошибке подготовки; независимые
снимки режима и сохранение исторического неизвестного происхождения.

В браузере на пользовательском STL подготовлены 9 сечений, 7 плоских участков
и 64 точки, JSON 32 488 байт. Проверены предупреждения о потере детализации,
переход images → hybrid, неизменность бюджета и количества CAD-версий.
Независимый агент проверил код и финальный диалог при 1280×720. Платного
эксперимента качества images против hybrid в этой проверке не было.

## Следующие отдельные эксперименты

Нативный backend: облако поверхности → обученный 3D-проектор → CAD-код, например
по архитектуре [CAD-Recode](https://arxiv.org/abs/2412.14042). Поддержка облака
требует соответствующей модели; сериализация координат в текст её не заменяет.

POD–QDEIM: поля расстояний семейства деталей на общей сетке → базис по обучающей
выборке → выбор узлов → локальное восстановление/измерения. Тестовые детали
исключаются из построения базиса. SVD координат `N×3` не служит кодом сложной
поверхности. Для незамкнутых mesh нельзя молча считать подписанное поле валидным.
Сжатие оценивается отдельно по геометрической ошибке и сохранению топологии.
Основа метода: [POD–DEIM](https://doi.org/10.1137/090766498) и
[Q-DEIM](https://arxiv.org/abs/1505.00370).
