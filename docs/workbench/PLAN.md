# Mesh2CAD Workbench — план реализации

Дата: 21 октября 2026. Статус: локальный прототип реализован агентами `gpt-6.1-sol / medium`; 103 теста и браузерные проверки пройдены. Независимая дизайн-проверка завершена после исправлений. Сравнительная Gauntlet-приёмка заблокирована несопоставимостью доступного эталона; победа не заявлена. Фактический результат и ограничения — в [IMPLEMENTATION.md](IMPLEMENTATION.md).

## Зафиксированные решения

- Локальная исследовательская рабочая среда с импортом геометрии, 3D-сценой, предсказаниями, оценкой и контекстным ассистентом справа.
- Начальный стек — Streamlit и собственный интерактивный компонент просмотра. FastAPI + HTML/JS/CSS допускается только после воспроизводимого провала обязательного UX-сценария.
- Пользователь выбрал Google AI Studio как эталон организации рабочего места. Google DeepMind — визуальное направление. Это разные роли референсов; публичная официальная библиотека компонентов DeepMind не предполагается.
- Исполнители и независимые проверяющие: `gpt-6.1-sol`, reasoning `medium`. Передавать узкие задания в свежем контексте, без полной истории чата и секретов.
- На данном этапе нет новых платных запросов к модели реконструкции. Для разработки использовать fake backend и сохранённые результаты.

## Экран и основные сценарии

```text
┌ Проект / деталь                 Сохранение · Статус · Настройки ┐
├─────────────┬─────────────────────────────┬─────────────────────┤
│ Файлы       │ Target / Candidate / Overlay│ Ассистент           │
│ Импорт      │                             │ Контекст версии     │
│ Проекты     │   Интерактивная 3D-сцена     │ Объяснить / Изменить│
│ Запуски     │                             │ Диалог              │
│             ├─────────────────────────────┤                     │
│             │ IoU · CD · F-score · ошибки │ Поле сообщения      │
│             ├─────────────────────────────┤ Запуск / Стоп       │
│             │ История версий и ветвлений  │ Модель · Бюджет      │
└─────────────┴─────────────────────────────┴─────────────────────┘
```

1. Импортировать файл → проверить геометрию → показать исходник и нормализованные координаты.
2. Выбрать модель, режим входа и бюджет → запустить реконструкцию → наблюдать реальные стадии без блокировки интерфейса.
3. Вращать, приближать, скрывать поверхности, включать каркас и прозрачность; сравнивать исходник и выбранную версию наложением. Split-режим с общей камерой — следующий проверяемый режим просмотра.
4. Выбрать любую сохранённую версию → увидеть именно её код, метрики, родителя и связанный диалог.
5. Спросить «почему неверен карман?» в режиме объяснения либо «открой карман спереди» в режиме изменения.
6. Изменение создаёт дочернего кандидата; он проходит sandbox, экспорт и evaluation. Исходная версия сохраняется. Ручное редактирование кода проходит тот же путь.
7. Остановить задачу, обновить страницу, открыть проект заново и продолжить без повторного списания за уже полученный ответ.
8. Экспортировать STEP, STL, CadQuery Python и отчёт JSON/CSV.

## Архитектура

`Streamlit UI → workbench service → SQLite + файлы артефактов → отдельный worker → backend / sandbox / evaluation`

- UI хранит выбранные ID, черновик и параметры отображения. Авторитетное состояние задач, версий и диалогов находится вне `st.session_state`.
- Одна последовательная очередь вычислений на старте. Транзакционное получение задачи, heartbeat, отмена, восстановление после смерти worker. UI опрашивает небольшие записи статуса; меши перечитываются только при изменении артефакта.
- `Asset`: исходный файл и хэш, формат, единицы/неизвестные единицы, нормализованный mesh, обе матрицы преобразования, диагностика импорта.
- `Candidate`: неизменяемый код и хэши артефактов, родитель, инициирующее сообщение, результат исполнения и статус.
- `Evaluation`: хэши обеих геометрий, система координат, версия метрик, параметры выборки, значения и причины недоступности.
- `Job`: снимок входа и настроек, стадия, статус, heartbeat, запрос отмены, usage и записи резервирования стоимости.
- `Conversation`: сообщения с зафиксированными asset/candidate/model ID. Поздний ответ нельзя привязать к уже переключённой версии.
- Секреты находятся только на стороне Python/worker. Не записывать ключи в исходники, SQLite, HTML, URL, логи и задания агентов.

### Подключение существующего кода

- Переиспользовать `geometry.normalize_mesh`, `render_views`, `render_comparison`, `evaluate_meshes`, `executor.execute_code`, хэши и проверку путей из `storage`.
- Сохранить CLI и строгую воспроизводимость `harness.run_experiment`; интерактивные задачи имеют отдельные manifests и правила возобновления.
- Подготовку одного импортированного asset выделить из STL/subset-сценария `dataset.prepare_dataset`, без фиктивных dev/test-наборов.
- Добавить протокол backend: generate, explain, cancellation, usage. Поднять проверенный OpenRouter-адаптер из исследовательских скриптов в пакет с тестами. Существующий аудит Codex не ослаблять.
- Текущие generation/execution блокирующие: потребуются отмена subprocess group и безопасная проверка cancellation на стадиях. Потоки UI не исполняют сгенерированный Python.
- Атомарные записи одного JSON не должны иметь нескольких конкурирующих писателей с одинаковым временным именем. SQLite и единственный владелец записи решают этот конфликт.

## Импорт и системы координат

- Первая поставка: STL, OBJ, PLY с треугольной поверхностью, OFF, GLB. Для каждого формата нужны настоящий fixture, успешный импорт и проверка экспортированной геометрии.
- OBJ не разрешает произвольное чтение внешних MTL/текстур. GLB сохраняет преобразования экземпляров сцены. Ограничить размер, число элементов, время и расход памяти импортера.
- PLY только с точками определяется как облако, а не как замкнутое тело; показать понятное сообщение и недоступность неподдерживаемых действий.
- STEP/STP — отдельный дополнительный CAD-import через CadQuery с сохранением B-rep, параметров тесселяции и исходника. Не обещать поддержку до прохождения fixture-теста.
- Внешние зависимости `.gltf`, архивы и новые форматы добавляются отдельными задачами, когда их загрузка действительно реализована.
- Нормализуется только target. Предсказание нельзя независимо подгонять. Исходные единицы/матрица сохраняются; экспорт в исходной системе координат — явная опция с проверкой обратимости.

## Метрики и выбор кандидата

- CAD validity, watertight/volume, компоненты, число вершин/граней.
- IoU через существующий manifold-путь только для применимых замкнутых объёмов.
- Symmetric squared Chamfer: сумма двух средних квадратов расстояний, 8192 точки на поверхность, seed 42; параметры и координаты видны в UI.
- Surface precision/recall/F-score при явно указанном пороге в нормализованных единицах, начальный порог 0.01.
- Симметричный H95: максимум 95-х перцентилей расстояний в двух направлениях по объявленной выборке; не называть его точным Hausdorff.
- Ошибка объёма `abs(V_pred - V_target) / V_target` при применимости; ошибка extents bounding box по трём осям.
- Для каждой метрики: направление улучшения, параметры, статус и причина отсутствия. `Not evaluated`, ошибка и неприменимость не превращаются в 0.
- В UI отдельно доступны «максимальный IoU», «минимальный CD» и ручной выбор. Для замкнутого target рекомендован IoU-first с CD при равенстве; при недоступном IoU показывать явный fallback. Политика фиксируется в конфигурации каждого нового запуска.
- Исторические benchmark-запуски сохраняют свой первоначальный отбор по CD. Не менять их задним числом.
- Регрессия: блок с карманом в `runs/openrouter-complex-20261020-01`: CD улучшился, IoU упал с 70.36% до 63.91%. UI обязан это показать и позволить выбрать первый вариант.

## Порядок работ и разделение агентов

| Этап | Владелец | Результат и условие перехода |
|---|---|---|
| 0. Эталоны и контракты | Lead | Зафиксировать реальные captures AI Studio/DeepMind, входные fixtures, критерии и baseline, сохранить незакоммиченные файлы |
| 1. Streamlit-проверка | UI builder | Три панели, живой 3D-компонент, fake chat/job, сохранение камеры и выбора; принять либо доказать необходимость fallback |
| 2. Домен и очередь | Engine builder | Импорт, SQLite, версии, evaluation, отмена, резерв бюджета, backend-протокол; UI и CLI не дублируют движок |
| 3. Рабочие сценарии | UI builder + Lead | Реальный импорт, prediction, чат explain/edit, история, экспорт и возобновление |
| 4. Проверки | Независимые critics | Browser evidence, проверки поведения и метрик, отдельная дизайн-приёмка |
| 5. Gauntlet-итерации | Lead + builder + свежий critic | Исправления по конкретным дефектам, затем финальная проверка целой среды |

Все роли используют `gpt-6.1-sol / medium`. Одновременно не более двух исполнителей с разными файлами и одного проверяющего вместе с lead; при лимите слотов роли чередуются. Конфликтующие записи, изменение зависимостей и интеграцию сериализует lead. Проверяющий не чинит работу, которую оценивает.

## Когда разрешён FastAPI + HTML/JS/CSS

После воспроизводимой проверки и попытки исправления через поддерживаемые API Streamlit:

- Обновление статуса/чата сбрасывает камеру, выбранного кандидата или черновик.
- Правый dock с независимой прокруткой и доступным composer не работает на 1440×900 / 1280×800.
- Viewer не может надёжно передать выбранную сущность или сохранить своё состояние.
- Просмотр репрезентативного mesh в 100 тысяч треугольников непригоден для интерактивной работы; большие mesh должны иметь облегчённое preview с неизменным оригиналом для evaluation.
- Решение требует хрупкой подмены внутреннего DOM Streamlit вместо устойчивого компонента.

Зафиксировать failing сценарий, запись/скриншот и последствия. При смене UI сохранить service, worker, persistence и fixtures; FastAPI не создаёт второй движок. Предпочтение стиля само по себе не повод менять стек.

## Приёмка

- Каждый заявленный формат импортируется; некорректные файлы и внешние пути отклоняются; instance transforms GLB проверены.
- Генерация и чат не блокируют viewport; камера, выбор и черновик переживают polling и обновление страницы.
- Путь import → predict → evaluate → explain → edit → compare → export работает с fake backend и реальным CadQuery sandbox.
- Объяснение не исполняется; изменение создаёт новую версию; поздний ответ не меняет чужой контекст.
- Отмена подтверждается UI без ожидания следующего полного rerun; worker достигает terminal status и сохраняет готовые артефакты.
- При смерти worker и перезапуске UI нет дублирующих оплаченных запросов. Неопределённые списания остаются резервами.
- Метрики проверены на совпадающих, сдвинутых, открытых и ошибочных геометриях; коррекция масштаба не маскирует ошибки.
- Бюджет включает generate/explain/edit/retries. Лимит не обходится несколькими одновременными кнопками. Токены и деньги учитываются отдельно.
- Desktop 1440×900 / 1280×800, tablet 768×1024 и mobile 390×844: нет перекрытого чата, потери выбора и переполнения страницы.
- Keyboard walkthrough, видимый focus, подписи и контраст; цвет не единственный носитель статуса.
- Существующие pytest/ruff-проверки проходят. Добавлены целевые integration/browser-проверки, а не тесты CSS-констант.
- Внешний вид проверен другим агентом по реальным скриншотам; интерактивность проверена сценарием, а не картинкой.
- Итоговая Gauntlet-приёмка записана только при фактическом прохождении критериев; неподтверждённые сравнения не объявляются победой.

## Ограничения бюджета и состояния репозитория

На момент планирования общий лимит reconstruction API из переписки — $0.50. В `runs/openrouter-complex-20261020-01/budget.json` есть измеренные расходы и резерв одного оборванного запроса; вместе с прежним мини-тестом консервативный учёт составляет около $0.119607. Перед реальными вызовами пересчитать остаток по ledger, неизвестное не обнулять. Кодинговые агенты Codex не относятся к этому API-ledger; экономить их расход узкими контекстами и заданным medium.

Не сбрасывать и не терять текущие staged/unstaged/untracked файлы. Существующие `cadfather`, `cadrille`, `DeepCAD`, исследовательские артефакты и окружения сохраняются. Коммит, публикация, внешний хостинг и изменение глобальной конфигурации не входят в этот план.
