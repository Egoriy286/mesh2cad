# Mesh2CAD: научная презентация

10 слайдов, LaTeX Beamer, 16:9. Содержание сверено с реализацией и сохранёнными
прогонами на 22 октября 2026 года. Исходный PDF использован как стилистический
ориентир; устаревшие сведения о четырёх видах, основной Chamfer-метрике,
Linux-only sandbox, будущем интерьерном наборе и оптимизации параметров заменены.

## Сборка

Основной файл: `main.tex`. Все картинки и численные значения уже включены,
поэтому для компиляции доступ к датасетам, API и каталогу `runs/` не нужен.
Готовая сборка также включена как `main.pdf`.

```sh
latexmk -xelatex -interaction=nonstopmode main.tex
```

Альтернатива: `tectonic main.tex`. Используются Beamer, fontspec, babel,
amsmath, amssymb, booktabs и graphicx. Шрифт Liberation Sans и его лицензия
включены в `fonts/`; устанавливать системные шрифты не нужно.
Предусмотрена ветка pdfLaTeX с кодировкой T2A.

`speaker-notes.md` содержит текст выступления и пояснения к ограничениям.
`references.bib` содержит библиографию. `results.tex` хранит значения для таблиц.

## Данные и смысл результатов

- В слайде 7 стоимость первого оркестратора относится только к детали
  `274a034e5c4ac827`: суммируются все пять вызовов её попыток. Стоимость всей
  очереди из трёх моделей не подставляется в сравнение одного объекта.
- У второго оркестратора стоимость включает анализ геометрии и оба ответа
  генерации, в том числе неисполняемый ответ в DeepCAD-пилоте.
- В DeepCAD-пилоте второго оркестратора доступно 8192 output tokens на вызов,
  у первого — 4096. Число программ и содержание визуального контекста различаются.
  Таблица не является экспериментом при равных бюджетах.
- Пилоты выполнены на последовательных версиях: в DeepCAD калибровка рендера v1,
  в Interior300 — v2 (учёт проекции bounding box и измеренные уровни глубины).
  После DeepCAD также уточнена формулировка запроса исправления.
- Сравниваются сохранённые пилотные запуски, а не средние метрики датасетов.
  Их нельзя включать в рейтинг опубликованных методов без общего протокола.
- В Interior300 улучшился основной объёмный IoU, но не все вспомогательные
  показатели. Missing surface вырос с 22.85% до 51.52%; это другая метрика
  (доля размеченных граней, а не объёмная ошибка).
- Второй оркестратор использует известный STL: из него получаются RGB/depth,
  чертёж, габариты, сечения, объём и центр масс. Это не image-only benchmark
  и не подключение произвольных фотографий/внешних depth-карт.
- Численная оптимизация параметров в представленных прогонах не выполнялась.
- Структура гипотезы и будущего исследования не означает, что сравнение
  с Qwen/Opus либо экономия API в 5–10 раз уже подтверждены.

## Проверяемость

`evidence.json` фиксирует исходные run ID, SHA-256 checkpoint и входных STL,
usage каждого вызова, статусы попыток, IoU, память, источник каждого изображения
и SHA-256 файлов реализации. Код на ветке `harness` содержит незакоммиченные
изменения; один HEAD не описывает эту версию, поэтому добавлены хеши файлов.

Числа: `run.json`, `memory.json`, `iou.json` существующих прогонов:

- `20261022T184742Z-b4c867e2` — первый оркестратор, выбранный объект DeepCAD;
- `20261022T184705Z-7cef923e` — второй оркестратор, DeepCAD;
- `20261022T185141Z-59366e3d` — второй оркестратор, Interior300.

Изображения — обрезанные без изменения геометрии фрагменты сохранённых рендеров.
Обрезка сохраняет одинаковую камеру внутри каждого сравнения.

Для обновления чисел и картинок в исходном репозитории:

```sh
python prepare_assets.py
```

Скрипту нужен Pillow. Он читает локальные checkpoint, не вызывает LLM и
не запускает реконструкцию или оптимизацию. Абсолютные пути к приватным ключам
и содержимое `.env` в проект не включены.
