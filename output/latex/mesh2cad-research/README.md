# Эффективный харнесс для Mesh2CAD

LaTeX Beamer, 22 слайда, 16:9. Основной файл `main.tex`, сборка `main.pdf`.
Авторы: Монастырев Егорий, Егорова Данаайа. Ментор: Дроздов Никита.

Презентация охватывает неформальную и формальную постановки, актуальность,
классы методов и ограничения, бенчмарки, решаемую проблему, полный цикл метода,
измеренные результаты, выводы и дальнейшие проверки. На отдельном слайде
показаны реальная программа CadQuery и геометрия её исполнения.
На слайдах оставлены краткие тезисы, подробное объяснение находится в заметках.
Схема цикла явно включает вход STL, подготовку видов, обратную связь и выход
с лучшим CAD. Эталонная сетка отдельно поступает в оценку.

Основные таблицы показывают новый трёхрежимный эксперимент 23 октября 2026:
`openai/gpt-6-luna` с одним ответом, та же модель с classic harness до пяти
генераций и `openai/gpt-6-sol` с одним ответом. Фактический N указан в таблицах.
План 50 деталей + 50 объектов ограничен бюджетом ключа. Все три условия используют
одни и те же объекты внутри домена, изображения, базовый промпт и правила оценки.
Первый ответ Luna общий для baseline и начала harness-цикла.

В слайдах использованы точные входные изображения и обратная связь нового
эксперимента. На детали `3376e6b0a71b3a98` показаны исходник и три результата
в одинаковой камере, без подгонки координат. Метаданные иллюстрации находятся
в `benchmark/example.json`, исходные метрики и проверка запросов - рядом.

## Пример CadQuery

`examples/frame.py` содержит полный исполнимый код рамки из первого ответа Luna
на детали `bc69e26be07daf52`. Код переформатирован без изменения операций.
`examples/frame.stl` и `images/cadquery-code-example.png` получены его исполнением.
В `examples/provenance.json` сохранены исходный путь и хеши, проверка валидности
и совпадения с первоначальной программой. Параметр `inner_x` меняет ширину проёма.

## Данные и воспроизведение

`benchmark-results.tex` и `images/benchmark-*.dat` содержат новые таблицы и графики.
`benchmark/` содержит отчёт, пообъектные метрики, протокол, бюджет, bootstrap-интервалы
и независимый аудит источников. Основные результаты находятся в
`output/benchmarks/20261023` исходного проекта. Полные запросы, ответы, код,
STL/STEP и checkpoints сохранены там локально в `runs/` и не входят в компактный
архив презентации.

Из корня проекта, без платных запросов:

```sh
.venv/bin/python -m mesh2cad.benchmark
.venv/bin/python scripts/summarize_benchmark.py
.venv/bin/python scripts/audit_benchmark.py
```

Последние две команды обновляют таблицы/текст выступления и проверяют
соответствие исходных файлов, запросов, результатов и оплаты. Новый платный
запуск требует явного `--run`; сохранённые завершённые объекты используются повторно.
Текст выступления генерируется из `speaker-notes.template.md` с подстановкой
измеренных метрик. Для правки структуры выступления меняйте этот шаблон.

`results.tex`, `paired-summary.json`, `benchmark-items.csv` и исторические части
`evidence.json` сохранены как материалы прежних пилотов. Они не являются источником
новых основных таблиц. `prepare_assets.py` относится к этим историческим материалам;
его запуск не обновляет новый эксперимент. Для новых чисел используется
`scripts/summarize_benchmark.py`.

Объёмный IoU считается по полным STL без выравнивания. Неудачная реконструкция
даёт 0 в основном среднем; доля пригодных объёмов указана отдельно. Необработанные
объекты не считаются измеренными неудачами. Bootstrap-интервалы описывают разброс
объектов, а не повторных ответов LLM. Базовый промпт classic говорит mechanical part
в обоих доменах; это ограничение переноса на интерьерные объекты.
