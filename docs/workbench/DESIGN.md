# Дизайн рабочей среды

## Источник и границы

Стиль: https://deepmind.google/. Организация рабочего места: Google AI Studio, прежде всего workspace с превью артефакта и контекстным чатом: https://ai.google.dev/gemini-api/docs/aistudio-build-mode.

Это предложенная дизайн-система приложения по наблюдаемым визуальным мотивам DeepMind, а не официальные токены или пакет Google. Не использовать логотипы Google/DeepMind и не создавать впечатление принадлежности продукта Google. Оригинальная композиция должна оставаться плотной рабочей средой.

## Desktop и адаптация

- При 1440px: левая панель около 224px, чат около 360px, сцена занимает остаток, верхняя строка 56px.
- Сцена получает приоритет площади; история и evaluation располагаются ниже неё. Код и технические логи открываются по запросу.
- У панелей независимая прокрутка. Composer виден при длинном диалоге; прокрутка чата не уносит сцену.
- На ширине 1000–1279px проекты сворачиваются в drawer. На 768–999px — вкладки «Модель / Чат / История». На телефоне — одна панель с сохранением контекста и состояния задачи.
- Камера, выбранная версия, черновик и запущенная задача не теряются при перестройке layout.

## Поведение сцены

Orbit / pan / zoom / fit; front / side / top / isometric; Target / Candidate / Overlay; отдельные visibility и opacity, wireframe. Autorotation выключена. Split-режим допускается при общей камере.

Легенда показывает, что именно отображается. Метрики, viewport, история и чат используют один selected candidate ID. Сообщение ассистенту фиксирует этот ID при отправке. Визуальное облегчение mesh не меняет геометрию, по которой считаются метрики.

## Состояния

Проверить: пустой проект; импорт; готовый target без prediction; генерация; исполнение; evaluation; объяснение; изменение; отмена запрошена; отменено; лимит бюджета; недоступная модель; повреждённый mesh; ошибка CadQuery; неприменимый IoU; ошибка метрики; успех без улучшения; открытая историческая версия.

Во время ошибки сцена и предыдущие результаты остаются доступны. Нет выдуманных процентов прогресса. Отсутствие метрики не выглядит как нулевое совпадение. Результат с худшим IoU не называется улучшением только из-за меньшего CD.

## Независимая дизайн-проверка

Проверяющий получает реальные neutral A/B captures, одну задачу сравнения и результаты обязательных проверок. Он не получает имён авторов, истории исправлений и желаемого победителя; не ищет соответствие A/B в файловых путях и ledger. Нельзя судить интерфейс только по исходникам.

Сравнение с AI Studio касается иерархии рабочего артефакта, следующего действия, модели/настроек и контекстного диалога. Проверки CAD-функций выполняются по нашему контракту отдельно. Нельзя выдавать сравнение разных задач/состояний за валидное слепое сравнение.

Скриншоты: 1440×900, 1280×800, 768×1024, 390×844. Запись сценария: import → orbit → predict → select history → explain/edit → compare → reopen → cancel. Keyboard-only: доступ к основным действиям, видимый focus, подписи кнопок, ясные статусы, доступный summary canvas. `Esc` закрывает временные панели, но не отменяет работу молча.

Дизайн-критик сообщает наблюдаемый главный дефект и доказательства, разработчик исправляет его, новый критик проверяет новую сборку. Полный цикл и условия завершения описаны в AGENT_BRIEFS.md.
