# Mesh2CAD · Harness

Оркестратор реконструкции STL в CadQuery с агентом OpenRouter, Streamlit GUI,
автоматической обратной связью, метриками и журналом событий. Ручной pipeline
импорта STL, просмотра и пошагового выполнения сохранён в отдельном режиме.

## Метод и сравнительный эксперимент

[Полный цикл с визуализациями](docs/method.md) описывает исходный STL,
нормализацию, изображения для модели, исполнение CadQuery и уточнение геометрии.
[Результаты эксперимента 23 октября 2026](output/benchmarks/20261023/README.md)
сравнивают один ответ `gpt-6-luna`, ту же модель с classic harness и один ответ
`gpt-6-sol` отдельно на деталях и предметах интерьера. Пообъектные метрики,
стоимость, bootstrap-интервалы и протокол сохраняются вместе с отчётом.

Новый прогон [50 сложных DeepCAD + 50 интерьерных STL](output/benchmarks/20261023-hard50-interior50/README.md)
использует classic harness и `gpt-6-luna`. Каждый домен разбит на группы
15 + 15 + 15 + 5. Лимиты: 16 000 выходных токенов на ответ и 1 000 000 токенов
на группу. Восемь групп работают параллельно, тяжёлая геометрия ограничена
двумя одновременными операциями. Детали выбраны по геометрии входных STL,
интерьеры - с балансом категорий, 40 IndoorCAD и 10 Poly Haven.

```sh
# Подготовка входов и снимков конфигурации, без генерации моделей:
uv run python -m mesh2cad.batch_benchmark --prepare
# Платный запуск / продолжение с сохранённых checkpoints:
uv run python -m mesh2cad.batch_benchmark --run --workers 8
# Отчёт по завершённому прогону, без платных запросов:
uv run python -m mesh2cad.batch_benchmark
```

Общая таблица и пообъектный CSV обновляются каждые 30 секунд. Завершённые
объекты не генерируются заново, оплаченные ответы сохраняются. Общий денежный
лимит закреплён в `budget.json` по доступному лимиту ключа перед запуском.

```sh
# Только пересчёт сохранённых результатов, без платных запросов:
uv run python -m mesh2cad.benchmark
uv run python scripts/summarize_benchmark.py
uv run python scripts/audit_benchmark.py
```

## Оркестратор

```sh
uv sync --extra dev
uv run streamlit run app.py
```

В боковой панели выберите **Оркестратор**, задайте OpenRouter API key (или
используйте `OPENROUTER_API_KEY` из `.env`), выберите датасет **DeepCAD** или
**Interior300**. Во вкладке «Новый запуск» выберите split, категории и модели.
Пустой список моделей означает отфильтрованный список, с учётом поля «Максимум STL».
По умолчанию запускаются до трёх dev-моделей, до пяти итераций на каждую.

После запуска GUI остаётся доступен. Лёгкая строка состояния обновляется каждые
две секунды; 3D-preview обновляется при изменении результатов. Скрытые вкладки
не вычисляются, завершённые запуски не опрашиваются. Worker работает в отдельном
процессе и переживает rerun или закрытие вкладки браузера. При остановке сервера
worker и CadQuery завершаются; продолжить можно из истории по сохранённому checkpoint.

Одновременно выполняется один тяжёлый запуск, остальные ждут в очереди без
расходования активного времени. Повторное нажатие запуска с теми же входами и
параметрами открывает уже существующую задачу.

**Память:** watchdog проверяет RSS worker вместе со всеми дочерними процессами
каждые 100 мс. Лимит по умолчанию **2048 МиБ**, доступен в «Лимиты и промпты»
и CLI `--memory-limit-mb`. При превышении дерево процессов завершается, checkpoint
получает причину `memory_limit`; оплаченные ответы и готовые CAD-файлы сохраняются.
Текущий RSS, пик и лимит видны в GUI и `memory.json`. Это контроль RSS с опросом:
между замерами возможен краткий выход за лимит. Ручной пересчёт IoU также изолирован
с лимитом 2048 МиБ и таймаутом 120 с. CadQuery отдельно ограничен 2048 МиБ.

Рендер использует ограниченные порции пикселей. Разметка missing surface проверяет
расстояния порциями и ограничивает детализацию до её выделения в памяти. IoU
по-прежнему вычисляется по полным STL. Для `distance_status=threshold_classification`
`max_distance` остаётся `null`, если есть missing: глобальное максимальное расстояние
не вычисляется; пороговая классификация сохраняется.

Один цикл:

1. Оркестратор проверяет SHA-256 STL, сохраняет снимок входов, нормализует модель
   и создаёт шесть RGB/depth-видов текущим рендерером.
2. `OpenRouterAgent` получает исходные виды и размеры, возвращает полный CadQuery-код.
3. Оркестратор выполняет код в существующей песочнице и считает настоящий объёмный
   IoU без подгонки положения или масштаба.
4. Агент получает ошибки исполнения либо IoU, missing surface и объёмную цветовую схему лучшего
   результата. Исходное изображение, лучшая программа и три последние итерации
   остаются в контексте. Следующая программа выполняется и оценивается автоматически.
5. Обработка останавливается при достижении целевого IoU, отсутствии улучшений,
   исчерпании итераций, токенов, активного времени или по кнопке «Остановить».

Лучшая программа сохраняется независимо от ухудшений в следующих итерациях.
Незамкнутый target получает статус `unscorable` без вызова LLM. Ошибка конкретного
STL не блокирует очередь. Ошибки API/песочницы останавливают весь запуск; временные
HTTP 408/429/5xx и сетевые ошибки имеют ограниченные повторы с backoff.

**Метрики:** лучший IoU на каждую модель, средний IoU по оценённым моделям, средний
по всей очереди (неоценённые учитываются как 0 только здесь), доля достигших цели,
валидные программы, число вызовов и итераций, input/output/total tokens, известная
стоимость из provider usage, время LLM/CadQuery и активное время запуска. Неизвестный
IoU или стоимость показываются как `—`; число ответов без usage/cost указано отдельно.
Missing — доля размеченных граней поверхности, а не объёмная метрика.

**Продолжение:** завершённые модели пропускаются; сохранённый ответ LLM используется
повторно без оплаты нового запроса. Прерванный CadQuery выполняется заново с тем же
кодом. Если процесс погиб до сохранения ответа HTTP, при продолжении запрос может
повториться: гарантировать отсутствие повторной оплаты в этом случае невозможно.
Кнопка остановки прерывает worker вместе с CadQuery через две секунды, если операция
не остановилась раньше. Незавершённый HTTP-ответ при этом может не сохраниться.
Бюджет токенов проверяется перед следующим
вызовом по полученному usage; текущий ответ может превысить остаток. После исчерпания
бюджета создайте новый запуск с большими лимитами.

GUI показывает очередь, историю, график IoU, 3D target/CadQuery, contrast overlay,
программы, ошибки, точные запросы/ответы и stdout/stderr worker. Можно скачать
STL/STEP, JSON, CSV-результаты и JSONL-логи. Ключ API не входит в артефакты.

**Консоль проекта:** общие логи GUI, датасета, OpenRouter, CadQuery и геометрии
выводятся в терминал запуска и `runs/logs/project.log` с ротацией (10 МБ × 4 файла).
Вкладка «Консоль проекта» показывает ограниченный хвост журнала, обновляет его
каждые две секунды и позволяет скачать файл. В логах есть начало/конец этапов,
время, память, ошибки и stdout/stderr CadQuery; ключи маскируются, изображения и
полные запросы туда не копируются. Точные запросы остаются артефактами итераций.

```sh
tail -f runs/logs/project.log
MESH2CAD_LOG_LEVEL=DEBUG uv run streamlit run app.py
```

Первая вкладка **«Запущенные · preview»** открывает сохранённый или текущий запуск.
Выберите STL-модель и версию — лучшую, последнюю или конкретную итерацию. Рядом с
preview показаны IoU именно этой итерации, объёмы исходника/результата и missing
surface. Можно переключить «Наложение» / «Рядом» / «Исходник» / «CadQuery», изменить
непрозрачность и открыть карту расхождений по шести видам. Кнопка
**«Пересчитать IoU по STL»** проверяет полные сохранённые сетки без изменения
checkpoint работающего оркестратора. До появления результата показывается исходный STL.

## Оркестратор 2

В боковой панели выберите **Оркестратор 2**. Он использует тот же цикл исполнения
CadQuery, оценки, исправлений и продолжения по checkpoint, но другой визуальный
контекст и отдельный этап анализа геометрии. История запусков каждого режима
показывается отдельно. Численная оптимизация удалена: код агента исполняется
напрямую, без поиска параметров, положения или масштаба.

1. Для каждого STL создаётся только линейная карта глубины: один лист с шестью
   видами в порядке top, left, right; isometric, bottom, front. RGB и чертёж
   не строятся и не передаются агенту.
2. Depth исходника и результата использует одинаковые камеры и near/far-плоскости,
   заданные габаритами исходника. Пустота кодируется нулём, поверхность — 1..255,
   ближняя поверхность светлее. Численные глубины сохраняются отдельно в NPZ.
   Калибровка и измеренные сечения STL входят в запрос агента.
3. Первый вызов агента составляет план: компоненты и их границы, отверстия,
   последовательность построения, неоднозначные размеры. Этот ответ сохраняется
   и повторно используется при продолжении. Он учитывается в токенах и стоимости.
4. Следующий вызов строит полный CadQuery-код. После исполнения агент получает
   фактический объёмный IoU, карту глубины лучшего CAD и численные ошибки по видам.
   В анализе и первой генерации передаётся один лист depth; в исправлении — два
   (исходник и лучший CAD). Цветная схема расхождений не используется.

В preview доступен блок **«Оркестратор 2 · карты глубины»**:
карты исходника и выбранной итерации, численные метрики и разбор геометрии.
Вкладки загружаются по выбору. Silhouette IoU и depth MAE описывают
видимые поверхности; итоговая оценка остаётся объёмным IoU полных STL без выравнивания.
Более подробная обратная связь не гарантирует высокий IoU на любом объекте;
точность зависит от выбранной модели и конструкции. Дополнительный анализ требует
одного вызова LLM на объект. Лимиты памяти, очередь и консольные логи общие с первым
оркестратором. Старые результаты численного уточнения сохранены для просмотра,
возобновление этого удалённого режима отключено.

Исторические пилоты предыдущей версии с RGB, depth и чертежом
(`openai/gpt-6-luna`, по две итерации на объект; это не проверка нового depth-only режима):
DeepCAD `274a034e5c4ac827` — лучший IoU **0.93979**;
Interior300 `indoorcad_d8441ba72f8641` — **0.70558 → 0.73106** после визуальной
обратной связи. Пики RSS worker вместе с CadQuery: 1039 и 1360 МиБ соответственно.
Запуски: `20261022T184705Z-7cef923e` и `20261022T185141Z-59366e3d`.
Это отдельные примеры, не средняя оценка датасетов. В первом запуске вторая
программа оказалась неисполняемой; лучший проверенный CAD сохранён. Формулировка
запроса исправления после этого уточнена; обе программы интерьерного запуска валидны.

```sh
uv run python -m mesh2cad.harness --orchestrator 2 --split dev --limit 1 --max-iterations 3
uv run python -m mesh2cad.harness --orchestrator 2 --manifest data/interior300/manifest.json --split all --limit 1
```

Артефакты второго режима:

```text
items/<id>/
  vision/depth.png, calibration.json, depth.npz
  analysis/request.json, response.json, geometry.json
  attempt-001/
    vision/depth.png, calibration.json, depth.npz
    visual-metrics.json
```

При загрузке STL удаляются только грани нулевой площади и треугольники с повторяющимися
индексами после объединения совпадающих вершин. Это устраняет дефект тесселяции
CadQuery без заполнения отверстий и перемещения вершин. Количество удалённых граней
сохраняется в `iou.json` и общих логах; реально открытые поверхности остаются неоценимыми.

## Interior300

Локальный `data/interior300/manifest.json` содержит **300 моделей**:
240 IndoorCAD и 60 Poly Haven. Поддерживается исходный manifest с `sha256`,
категориями, источниками и идентификаторами с подчёркиваниями; переупаковывать STL
или переписывать manifest не нужно. Имена, категории и источники сохраняются в
checkpoint и CSV результатов.

В этом наборе **118 объёмных моделей** и 182 незамкнутые/необъёмные сетки.
По умолчанию включён фильтр «Только модели для объёмного IoU». Его можно снять
для просмотра всех 300 объектов. Для необъёмной сетки IoU остаётся недоступным;
оркестратор проверяет геометрию перед вызовом агента. Официального dev/test
разбиения у этой локальной коллекции нет: используется `all`.

Каталог показывает готовые миниатюры и позволяет открыть 3D выбранного STL.
Для крупных моделей 3D-preview ограничен 40 000 гранями с сохранением координат;
**расчёт IoU использует полные STL**, без выравнивания или масштабирования результата.
Промпт нового запуска Interior300 описывает реконструкцию мебели и предметов интерьера.

Тот же оркестратор доступен из CLI:

```sh
uv run python -m mesh2cad.harness --split dev --limit 3 --max-iterations 5 --target-iou 0.9
uv run python -m mesh2cad.harness --resume runs/harness/<run-id>
uv run python -m mesh2cad.harness --manifest data/interior300/manifest.json --split all --limit 1
```

Локальный `data/deepcad/manifest.json` фиксирует 10 dev + 100 test STL из DeepCAD.
Хеши STL проверяются перед созданием запуска, а старые кешированные изображения
не требуются. Для локального каталога STL можно создать такой же manifest через
`python -m mesh2cad.dataset --source-dir /path/to/stl --output data/custom` и указать
его путь в GUI либо через `--manifest` в CLI.

```text
runs/harness/<run-id>/
  run.json                  # атомарный checkpoint, конфигурация, метрики
  manifest.json             # снимок manifest и закреплённого источника
  inputs/<id>.stl           # неизменяемые входы с SHA-256
  events.jsonl              # события этапов, повторы API и ошибки
  results.csv               # одна строка на STL; доступен и в живом GUI
  items/<id>/
    target.stl, target.png, normalization.json
    attempt-001/
      request.json, response.json, code.py, attempt.json
      execution.json, iou.json, difference.json, overlay.png
      cadquery/
        candidate.stl, candidate.step, stdout.log, stderr.log, traceback.txt
```

`mesh2cad/agent.py` описывает интерфейс `CadAgent` и агент OpenRouter;
`mesh2cad/harness.py` управляет очередью и жизненным циклом без зависимости от GUI;
`mesh2cad/harness2.py` реализует второй цикл, `mesh2cad/vision.py` — карты и метрики глубины;
`mesh2cad/harness_ui.py` реализует Streamlit-панель. Для другого агента передайте
реализацию `CadAgent` в `Orchestrator(..., agent=...)`.

## Что осталось

```text
app.py                    Streamlit: импорт STL, 3D-просмотр, pipeline
mesh2cad/agent.py         агент OpenRouter и интерфейс CadAgent
mesh2cad/harness.py       оркестратор, очередь, checkpoint, лимиты, CLI
mesh2cad/harness_ui.py    Streamlit GUI: управление, метрики, логи, история
mesh2cad/preview.py       ограниченный 3D-preview и полная проверка IoU сохранённых STL
mesh2cad/geometry.py      загрузка STL, нормализация, RGB/depth 512×512, IoU
mesh2cad/pipeline.py      точный запрос к OpenRouter, разбор ответа, артефакты
mesh2cad/prompts.py       system prompt и запрос по умолчанию
mesh2cad/executor.py      Seatbelt / restricted-запуск кода
mesh2cad/_worker.py       CadQuery worker: r -> STEP/STL
mesh2cad/dataset.py       воспроизводимая подготовка DeepCAD
mesh2cad/storage.py       атомарная запись JSON
data/deepcad/             локальный датасет (110 STL, manifest)
tests/                    проверки без сетевых вызовов
```

Удалены внешние репозитории `cadfather`, `cadrille`, `DeepCAD`, старые FastAPI,
кастомный Three.js-компонент, прежний CLI/harness, docs и тесты прежней рабочей среды.
Исторические `runs/` и остальные каталоги `data/` не удалялись.

## Экран

1. **Импорт и просмотр.** Загрузите STL или выберите файл из `data/deepcad/meshes`.
   Слева интерактивная 3D-модель, справа размеры и статистика.
2. **Pipeline.** Находится сразу под просмотром:
   - **1 · Нормализация** — центр bounding box в 0, длиннейшая сторона в 1;
     матрица, границы и normalized STL показаны полностью.
   - **2 · Изображение для LLM** — шесть видов: top (+Z), left (−X), right (+X),
     isometric (снизу-спереди), bottom (−Z), front (−Y). В LLM уходит один
     contact sheet **1536 × 1024**: сетка 3×2, в каждом тайле 512×512 RGB и его
     depth смешаны 50/50 в одно изображение, без рамок и подписей. Фон чёрный;
     ближе — светлее, дальше — темнее. Отдельные RGB и depth-тайлы доступны в
     блоке «Отдельные тайлы и метаданные», в ZIP и в артефактах.
   - **3 · Ввод** — редактируемые system prompt и запрос пользователя, модель,
     reasoning effort. Ниже показан точный JSON запроса; base64 сокращён только
     в предпросмотре, в скачиваемом `request.json` он полный.
   - **4 · Ответ** — кнопка отправки в OpenRouter, сырой ответ, usage и извлечённый
     CadQuery-код.
   - **5 · CadQuery и IoU** — кнопка выполняет ровно показанный код в отдельном
     процессе (macOS Seatbelt или restricted на других ОС). Результат показывается
     отдельно и в наложении: **зелёный — совпадение объёмов**, **синий — CAD за
     пределами исходного mesh**, **красный — недостающий объём CAD**.
     Цвета определяются настоящими булевыми операциями: пересечение, CAD минус
     исходник и исходник минус CAD. Заполненное CAD отверстие исходника тоже
     относится к синему избытку. IoU считается без выравнивания и масштабирования.
     В листе из шести видов яркость каждого цвета линейно кодирует глубину:
     **светлее — ближе, темнее — дальше**. Оттенок сохраняет смысл области,
     яркость не означает величину ошибки. Near/far-плоскости фиксируются по
     исходному mesh с запасом 0.05 норм. ед. для каждого вида и сохраняются между
     итерациями; влияние освещения отключено. Яркость меняется от 35% до 100%.
     Численная калибровка передаётся агенту вместе со схемой и сохраняется в
     `overlay-depth-calibration.json`; в preview она входит в `overlay-solid.json`.
     Вращаемое 3D-наложение использует обычное освещение; глубину кодирует PNG-лист.
     Missing surface остаётся отдельной метрикой по граням и не равен доле красного объёма.
     Схема `overlay-solid.png` 1536×1024 содержит шесть видов; 3D-наложение использует
     те же области и цвета. Расчёт в отдельном процессе: лимит RSS 2048 МиБ,
     таймаут 120 с. Результат кешируется по SHA-256 обоих STL и версии схемы.
     Для открытых сеток такая объёмная разметка недоступна. Старые исходные артефакты
     сохраняются; новая схема записывается отдельно. В оркестраторе 2 агенту по-прежнему
     передаются только карты глубины.
   - **6 · Улучшение** — кнопка «Улучшить». В улучшение уходит **не исходный лист,
     а контрастная схема** `overlay.png`; запрос пользователя тот же. В system prompt
     добавляется текущий CadQuery-код и описание цветов overlay. Ответ проходит
     тот же pipeline: новый код, CadQuery, IoU, объёмная цветовая схема и новая итерация.

Каждый запуск/итерация сохраняется в `runs/ui/<время>-<id>/`:

```text
source.stl
llm-images/
  llm-input.png        # стартовый contact sheet 1536×1024
  contrast-overlay.png # схема 1536×1024, уходит в improve-запрос
renders/
  top-rgb.png     # отдельные тайлы 512×512
  top-depth.png
  left-rgb.png
  left-depth.png
  right-rgb.png

  isometric-depth.png
  bottom-rgb.png

  front-depth.png
```

## Ключ OpenRouter

Ключ читается из `OPENROUTER_API_KEY` или из локального `.env`:

```sh
OPENROUTER_API_KEY=...
```

`.env` добавлен в `.gitignore`. В интерфейсе ключ скрыт, хранится только в памяти
сессии и не записывается в `runs/`.

## CadQuery

Код модели выполняется только после ответа LLM и всегда в отдельном процессе:

- **macOS** — Seatbelt (`/usr/bin/sandbox-exec`), если он доступен;
- **Windows / Linux / другие ОС** — restricted subprocess с Python audit hooks.
  Он блокирует сеть, создание процессов, `ctypes`, опасные импорты и доступ к
  файлам вне папки запуска. Разрешены только импорты `cadquery` и `math`.

Restricted backend — defense in depth, а не полноценная kernel-песочница.
На macOS можно принудительно выбрать backend через `MESH2CAD_SANDBOX=seatbelt`
или `MESH2CAD_SANDBOX=restricted`; по умолчанию `auto`. Seatbelt на не-macOS
возвращает `sandbox_error`.

Worker принимает переменную `r` типа `cq.Workplane`, проверяет валидность и
положительный объём, затем экспортирует `candidate.step` и `candidate.stl`.
IoU считается через `manifold3d`; если тела не замкнуты или boolean-операция
недоступна, в интерфейсе показывается причина, а не выдуманный ноль.

## Проверки

```sh
.venv/bin/python -m pytest
.venv/bin/ruff check app.py mesh2cad tests
```

Тесты проверяют нормализацию, 12 тайлов 512×512 (RGB + depth, чёрный фон),
общий sheet 1536×1024 (RGB+depth 50/50), структуру запроса, извлечение кода, сохранение артефактов,
настоящий CadQuery-экспорт в Seatbelt/restricted, блокировку опасных операций,
IoU на совпадающих/сдвинутых/разъединённых телах, красную зону отсутствующей
геометрии и контрастную overlay-схему для улучшения. Сеть не используется.
Harness-тесты используют предсказуемые ответы агента и настоящий CadQuery:
исправление кода и геометрии, сохранение лучшего результата, API backoff,
отмена и восстановление без повторного LLM-запроса, лимиты, блокировка worker,
хеши датасета и управление через Streamlit AppTest.
