# Задания агентам и порядок интеграции

Общий контракт: PLAN.md и DESIGN.md. Все роли — `gpt-6.1-sol`, reasoning `medium`. При создании subagent явно задать модель/effort и свежий контекст; полную переписку и ключи не передавать. Дальнейшее самостоятельное разрастание дерева агентов запрещено без поручения lead.

## Lead / интегратор

Прочитать применимые project instructions, PLAN.md, DESIGN.md и HANDOFF.md. Сохранить текущее состояние незакоммиченной работы. Согласовать контракты и границы файлов до параллельных изменений. Владеть pyproject/lockfile, запуском worker/UI, интеграцией, общим бюджетом, browser evidence и Gauntlet ledger. Ничего не публиковать автоматически.

Сначала провести Streamlit-проверку с fake backend. По её результату зафиксировать стек и не переписывать его без подтверждённого нарушения acceptance criteria.

## Engine builder

Область: новые workbench/domain/storage/jobs/import/evaluation/backend-модули и целевые тесты; существующий CLI сохраняется. С UI builder заранее согласовать контракты вызовов и событий.

Поставить: Asset/Candidate/Evaluation/Job/Conversation; SQLite и файлы; импорт заявленных форматов; worker с отменой/heartbeat/recovery; неизменяемую историю и ветвления; OpenRouter и Codex adapters без ослабления sandbox/аудита; разные response contracts для explain и edit; бюджет с резервами неизвестных вызовов; метрики с параметрами и причинами недоступности; явные политики выбора версий. Исторические benchmark-каталоги открываются read-only.

Доказательства: fixtures каждого формата, scene transforms, запрет внешних путей, круговой переход координат, cancellation/restart/idempotency, отсутствие дублирующих запросов, pocket-regression и обязательные существующие тесты. Не делать новые платные вызовы для unit/integration-проверок.

## UI builder

Область: Streamlit app, 3D-компонент, theme/tokens, браузерные сценарии и UI-документация. Не внедрять второй backend в обработчики кнопок.

Поставить: рабочую среду из трёх панелей, viewport с overlay и сохранением камеры, историю и метрики выбранной версии, контекстный чат справа, настройки модели и бюджета, объяснение и редактирование, editor/execute/evaluate, отмену и экспорт. Показать все состояния из DESIGN.md. На первом этапе fake backend, затем интеграция service. Заявлять лишь реализованные форматы.

Доказательства: рабочий локальный URL, browser recording ключевого сценария и captures разных размеров. При Streamlit-blocker предоставить минимальное воспроизведение, проверить поддерживаемые component/state APIs и передать решение lead; fallback должен сохранять слой service и worker.

## Независимый behavior reviewer

Read-only. Проверить import → prediction → evaluate → explain → edit → compare → export → refresh/reopen/cancel, а также ошибки и бюджет. Сверить UI с артефактами и хэшами, применимость IoU, параметры CD/F-score/H95, происхождение выбранной версии и ветки. Проверить, что ошибка/пустота/неприменимость не маскируются числом 0 и что «лучший CD» не выдаётся за «лучший IoU».

Воспроизводить дефекты и предъявлять конкретные доказательства. Не править собственные находки; изменения делает builder.

## Независимый design critic

Read-only, отдельный от UI builder. Передавать только цель, нейтральные артефакты, условия сравнения, judge question и обязательные gates. Проверить реальные рендеры и взаимодействия по DESIGN.md. Не передавать ему обоснования builder, прежние вердикты или mapping A/B. После существенно изменённой сборки создавать свежего critic с теми же настройками модели.

## Gauntlet Loop

Использовать Codex-адаптацию Gauntlet Loop, commit `a674e37d58d34e8e50b858fb7bd1b1bb8dc0b0cc`:

- [SKILL.md](https://github.com/thors-github/gauntlet-loop-codex/blob/a674e37d58d34e8e50b858fb7bd1b1bb8dc0b0cc/.agents/skills/gauntlet-loop/SKILL.md)
- [critic contract](https://github.com/thors-github/gauntlet-loop-codex/blob/a674e37d58d34e8e50b858fb7bd1b1bb8dc0b0cc/.agents/skills/gauntlet-loop/references/critic-contract.md)

Прочитать инструкции и зависимости до запуска цикла. При использовании helper scripts получить их из этой же ревизии в отдельный служебный каталог, проверить исходники; глобальные hooks/автоматизации не нужны. При распространении skill сохранять его attribution/NOTICE.

На старте сохранить реальные доступные captures выбранного Google AI Studio workspace и DeepMind с URL, датой, размерами, состоянием, хэшами; ссылка без локального capture недостаточна. Сравнивать организацию работы в эквивалентных состояниях; требования к CAD-функциям — отдельные детерминированные gates. Если ссылка требует недоступного входа или сопоставимость не обеспечивается, описать это и исправить пакет сравнения, не выдумывать победу.

Вести `state.json`, `history.jsonl`, `progress.md` через инструменты Gauntlet вне исходников. Сохранить исходную и лучшую работоспособную версии. После каждого содержательного изменения: проверки → запуск и осмотр → нейтральный пакет A/B → свежий read-only critic → фиксация результата → исправление главного подтверждённого дефекта. Использовать output contract critic-contract.md; ничья, недостаток доказательств и невалидное сравнение не являются победой.

Завершение: все gates из PLAN.md проходят и отдельный финальный critic принимает интегрированную рабочую среду по согласованному вопросу сравнения; хэши проверенного результата не изменились. Не подменять это фиксированным числом кругов или самопроверкой builder. При невозможности продолжить — конкретный blocker и сохранённое состояние, без ложного заявления о готовности. Экономить расход узким объёмом исправлений и контекста, а не пропуском проверок.

## Пакет передачи результата

Команда запуска, локальный адрес, документация форматов и поведения метрик; проходящие целевые тесты; captures/recordings и независимые вердикты; путь к Gauntlet run; известные ограничения; список изменённых файлов и состояние бюджета. Не включать секреты и не смешивать плату за reconstruction API с расходом кодинговых агентов.
